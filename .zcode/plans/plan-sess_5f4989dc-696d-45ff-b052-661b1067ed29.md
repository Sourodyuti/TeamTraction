# Plan: Legilimens Command-Center Dashboard

## Goal
Rebuild `/dashboard` into a single, polished, tabbed command center that visualizes **everything** a judge or developer needs to see — the full Muffliato → Marauder's Radar → Accio (Actian VectorAI) → Gemino (Gemini/NVIDIA) → Sonorus (ElevenLabs) → Pensieve pipeline — using **only the existing typed `api` client + WebSocket hooks** (no backend changes, per your choice).

## Key findings that drive the plan
1. **Two real bugs make the current analytics render empty/broken** (must fix):
   - `api.getDensity` (`frontend/src/lib/api.ts:67`) is typed `{ts,density}[]`, but the backend (`backend/routers/analytics.py:127-141`) returns **`{data:[{ts, type}]}`** — raw events, not density. Density must be derived client-side.
   - `api.getCohortHeatmap` (`api.ts:71`) is typed `CohortCell[]` with fields `{concept_node, hour, avg_density}`, but the backend (`analytics.py:143-160`) returns a **map** `{[concept_node]:{lost, gotit}}` — there is no `hour` or array. This is why the Pensieve heatmap shows nothing.
2. **`/health`, `/metrics`, `/retrieval/health`, `/vision/health`, `/transcription/status`, and `/analytics/seed` exist but are not consumed by any frontend page.** The dashboard has no KPIs, no system-health panel, and no way to populate demo data.
3. **The `latency_badge` WS message** (`types.ts:91`) already carries flat per-stage ms (embedding/retrieval/gemini/elevenlabs/total) — perfect for a headline gauge, but currently only shown as one inline string.
4. Existing, reusable assets: D3 `RadarHeatmap` (`components/radar/RadarHeatmap.tsx`), Recharts `Timeline` (`components/timeline/Timeline.tsx`), `ConfusionOverlay`, `LatencyBadge`, `useRadarData`, `useWebSocket`, `useScreenCapture`, `useAuth`, and the Hogwarts design tokens (`lib/design-tokens.ts`) + `globals.css`.

## Locked decisions (from your answers)
- **Data layer:** extend the existing `api` client + WS hooks only. **No backend/SDK endpoint additions.**
- **Layout:** rebuild `/dashboard` as a tabbed page (Live Radar / Analytics / AI Pipeline / System).
- **Demo data:** real live data by default + prominent **"Load demo data"** (calls existing `POST /analytics/seed`) and **"Trigger confusion wave"** (sends a burst of `lost` WS pings from N distinct students on one concept → crosses the real ≥2-students/20s threshold → fires the real Accio pipeline → produces a real `latency_badge` and analogy).

## Demo-data strategy (no backend changes)
- **Load demo data** → `api.seedDemo(1)` called 2-3× (each adds 6 rows across `chain_rule`/`gradient_descent`) → analytics tabs populate immediately.
- **Trigger confusion wave** → `useConfusionWave` sends ~6 staggered `lost` pings from distinct `student_id`s on one concept via the live WS → backend `ThresholdTracker` (`websocket.py:131`) fires → real Accio runs → real `latency_badge` + `analogy_ready` arrive → radar/pipeline light up. Honesty-preserving: it's real data flowing through the real pipeline, just initiated from the dashboard.
